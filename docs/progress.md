## Questions waiting for the user
- **A pool job's error lines show when its job returns (9.96; a known limitation, needs your OK).** What you see: in a pooled run (a copy's, a listing's or a removal's jobs), a job hands its error lines back with its result and hpcp prints them then: seconds after the failure among small files, later where a large file follows the failed one in the same job. A job that never returns (a stop with Ctrl-C, a worker killed or out of memory, one hung on a dead mount) shows none of the lines it held; 9.95 printed each as it happened (with an empty line before many of them, or on the progress frame). The error list and the exit status are as in 9.95, and a rerun meets the same files again; with `-s` every line prints at once. Why not fix: only the process that draws the progress line knows whether it is open, so a worker printing its own lines is how 9.94 and 9.95 put them on the frame or after an empty line (the blank lines this version removes); sending each line at once needs a second channel from every worker beside the results, which a killed worker can leave half written. Revisit when: an operator misses a line a stopped or killed run held, or the jobs get such a channel for another reason. Options: **(1) a known limitation, with one README line (recommended)** / (2) build the second channel in 9.96 (more parts, a later release). Your words it touches: "It NEEDS to print interm outputs when it is removing in command line" (2026-11-16): the progress line itself is live; only the error lines wait for their job. Waits on it: only the entry's text; 9.96's fix round goes on.
